# Distance model v1: research notes

Label correction, 2026-11-12: these original design notes used the recorded labels. The user subsequently confirmed that recorded 0 stays 0 and recorded 2–9 cm means 1–8 cm. The active model is [v2](../models/v2/README.md), trained with `raw-training-data/1/label_corrections.json`. References below to a 0–2 cm gap and original endpoints describe the superseded labeling.

Researched 2026-11-12 against primary documentation. Scope: PC training/inference first; preserve a practical route to the existing classic ESP32 later. These are candidate designs and validation recommendations, not measured accuracy or a deployment decision.

## What the current labels can establish

Task context: four MLX90393 sensors provide 12 XYZ inputs; optionally append four magnitudes `sqrt(x*x+y*y+z*z)` for 16 features. The measured distances are 0, 2, 3, 4, 5, 6, 7, 8 and 9 cm, with repeated approximately three-second trials.

A scalar regressor can output 4.37 cm even when no 4.37 cm label exists. That capability does not establish accuracy between labels. Rounding a prediction to 0.5 cm only sets the display increment. The unmeasured 0–2 cm interval deserves particular attention. New physical measurements at half-centimetre points are the decisive interpolation test; synthetic intermediate labels are not independent evidence. These are methodological inferences from the supplied sampling design.

Compare XYZ with XYZ-plus-magnitudes on the same folds. Magnitudes are deterministic derived inputs, so they add useful nonlinear representation rather than new sensor information. Preserve axis order, units, sensor identity, baseline handling and filtering in a versioned feature contract. Any learned baseline must use only information available to the live predictor.

## Compact candidate models

All size figures below are calculations for float32 learned parameters, excluding code, input scaling, metadata and working memory. They are not ESP32 firmware measurements.

| Candidate | Rationale and limit | Approximate parameter storage |
| --- | --- | --- |
| Linear ridge | Minimal reference model; L2 regularization controls coefficient size. Continuous but may underfit the sensor-to-distance curve. | 13 or 17 coefficients including intercept: 52 or 68 bytes. |
| Degree-two ridge | Adds squares and cross-sensor interactions while keeping a simple dot product. Continuous; regularization and held-distance checks must control overfit. | `1+p+p*(p+1)/2`: 91 coefficients at 12 inputs or 153 at 16, i.e. 364 or 612 bytes. |
| Small Gaussian RBF basis plus ridge | Choose a bounded set of training-only centres; fit a scalar linear combination of Gaussian responses. Smooth local nonlinear candidate; kernel width matters, and far-from-centre predictions need an explicit validity check. | At 16 inputs, 9–32 centres plus weights, one width and intercept: approximately 620–2,184 bytes. |
| Tiny MLP | Test e.g. 12/16 → 16 → 8 → 1, with ReLU or tanh hidden activations and a linear output. Continuous mapping; fitting stability and unseen-distance behavior must be demonstrated. | 353 or 417 weights/biases: 1,412 or 1,668 bytes. |
| Bounded random forest | Useful nonlinear PC comparator. Ordinary trees predict a constant within a leaf; averaging trees still yields a stepwise mapping, so a strong score on known distances may hide poor interpolation. Bound tree count, depth and leaf size. | Depends on measured node count; do not infer embedded size from a pickle. |

Ridge minimizes squared error plus an L2 penalty. PolynomialFeatures explicitly generates squares and interaction terms. These definitions support the two smallest baselines. The storage calculations and candidate sizes are engineering deductions. [Ridge documentation](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.Ridge.html), [PolynomialFeatures documentation](https://scikit-learn.org/stable/modules/generated/sklearn.preprocessing.PolynomialFeatures.html).

The documented Gaussian kernel is `exp(-gamma * ||x-c||²)`. Full kernel ridge produces a non-sparse solution, making inference grow with the number of retained training samples. A deliberately small basis avoids retaining thousands of correlated frames. Nyström is an official alternative that approximates a kernel map with a specified subset of training points; a hand-selected prototype RBF basis is a separate, simpler candidate. Choose centres inside each training fold. [RBF kernel](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.pairwise.rbf_kernel.html), [Kernel ridge guide](https://scikit-learn.org/stable/modules/kernel_ridge.html), [Nyström documentation](https://scikit-learn.org/stable/modules/generated/sklearn.kernel_approximation.Nystroem.html).

MLPRegressor exposes hidden-layer sizes, ReLU/tanh activations, L2 regularization, and weight/bias arrays. Its docs suggest LBFGS can work well on small datasets. Its automatic early-stopping split does not accept trial groups; use external group-aware validation instead of interpreting that split as trial-independent evidence. Forest documentation defines terminal-node means and averaging across trees; the stepwise conclusion follows from those operations. [MLPRegressor](https://scikit-learn.org/stable/modules/generated/sklearn.neural_network.MLPRegressor.html), [RandomForestRegressor](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.RandomForestRegressor.html).

## Validation that answers the intended question

1. **Repeatability at measured distances:** identify each complete trial using a globally unique recording/trial key. Keep every row or derived window from that trial in one fold. Prefer balanced folds that hold out repeats at every distance. If recording sessions share setup or drift, additionally hold out entire sessions when possible. Thousands of nearby rows are not thousands of independent experimental repeats. Group-wise validation is explicitly intended for dependent samples from experiments. [Grouped cross-validation guide](https://scikit-learn.org/stable/modules/cross_validation.html#cross-validation-iterators-for-grouped-data), [GroupKFold](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.GroupKFold.html).
2. **Interpolation:** separately withhold all trials at one interior distance, train on the remaining distances and evaluate the withheld distance. Repeat for 2–8 cm. Holding out 0 or 9 cm is an extrapolation check and should be reported separately. This is a domain-specific use of LeaveOneGroupOut, with distance as the group, rather than trial. [LeaveOneGroupOut](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.LeaveOneGroupOut.html).
3. **No preprocessing leakage:** learn scalers, feature selection, prototype centres, and tuning choices only from training folds. Split before learning these transformations; a Pipeline helps enforce the rule. Any overlapping time windows inherit their source trial's group. [Common pitfalls: data leakage](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage).
4. **Report useful errors:** MAE and RMSE in centimetres, signed bias, per-distance error, trial-level error distributions and within-trial prediction jitter. Give trials/distances equal reporting weight so a longer file cannot dominate. State clearly when a score helped select the model; retain new recordings as a later independent test. MAE/RMSE are standard regression losses; the weighting and jitter checks are task-specific recommendations. [MAE](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.mean_absolute_error.html), [RMSE](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.root_mean_squared_error.html).

If only one independent trial exists at a distance, that distance has no evidence for repeatability from unseen trials. A held-distance test also does not establish accuracy at unmeasured half-centimetre positions. The next recording round should include fresh 0.5 cm steps, especially near errors, plus changed recording sessions and realistic placement/orientation variation within the intended operating conditions.

## Preserve an embedded route without committing now

**Plain C/C++ arrays:** ridge needs scaling and dot products; quadratic ridge adds bounded products; a small RBF basis adds squared distances and `expf`; the tiny MLP needs dense loops and ReLU/tanh. All can store constant weights and use fixed-size working buffers, with no Python or model interpreter on the board. This is an implementation deduction from the model equations, not a promise about compiled size or speed. Export the feature contract, transforms, coefficients, valid operating range and reference input/output vectors alongside the PC model. Later compare the C predictor against PC outputs before board integration.

**TensorFlow Lite Micro / LiteRT for Microcontrollers:** an available option for a later neural-network model. Google's current workflow is train, convert, turn the model into a read-only C byte array, register supported operators, and run the C++ interpreter. The framework supports a limited operator subset and does not train on-device. The tiny sine-regression example demonstrates a scalar-output use case. [Microcontrollers overview](https://developers.google.com/edge/litert/microcontrollers/overview), [Getting started](https://developers.google.com/edge/litert/microcontrollers/get_started).

The tensor arena also holds intermediate and persistent allocations; model-file size alone is not the RAM budget. Audit arena use and total application free memory when integration is actually attempted. [TFLM memory management](https://github.com/tensorflow/tflite-micro/blob/main/docs/memory_management.md).

Espressif maintains `esp-tflite-micro` for ESP-IDF, integrates ESP-NN and explicitly lists a classic ESP32/240 MHz benchmark. Its current README supports ESP-IDF 5.1–6.0, with 5.2 outside CI, and marks 5.0 and earlier unsupported. Thus the chip has an official route, but compatibility with the project's exact Arduino/PlatformIO/IDF versions must be checked later. The published person-detection benchmark is not a latency estimate for this distance model. [Espressif repository and support policy](https://github.com/espressif/esp-tflite-micro), [ESP Component Registry](https://components.espressif.com/components/espressif/esp-tflite-micro).

For v1, compare the small continuous candidates on PC, preserve compact artifacts, and select using both unseen-trial and held-distance evidence. Delay board runtime selection and quantization until fresh measurements establish which model behavior is worth preserving.
